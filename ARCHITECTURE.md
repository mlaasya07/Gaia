# Architecture and rules

The rules every change to Gaia should follow. For the full picture of what Gaia is, read [Details.md](Details.md).

## Structure

- The simulation engine (`src/engine/*`, `src/scenarios/*`, `src/lib/useSimulation.ts`) runs entirely in the browser. Keep it client-side with no backend calls, so playback, pause and reset behave the same everywhere.
- One simulation is shared by every page. `SimProvider`, `RoleProvider` and `ThemeProvider` live at the root, so all pages see the same running twin. Read it with `useSim()`. Never call `useSimulation()` inside a route.
- `backend/` is the Python research pipeline (Streamlit dashboards, LACD experiments, dataset scripts). It is not served by the web app. Its only bridge to the web app is two exported files in `public/data/`.

## Data files

- `/evidence` reads only `public/data/evidence.json`, generated by `backend/gaia/lacd/experiment.py`.
- `/research` reads only `public/data/research.json`, generated by `backend/gaia/export_research.py`. The learned policy was trained on the Python simulator, so it is shown as research evidence next to the live twin and is never wired into `src/engine/*`. Do not run PyTorch in the browser.
- Never hand-edit either file. Regenerate them from `backend/`.

## Interface

- Roles (`src/lib/roles.ts`) are an interface permission model, not security. There is no login and no server, so anyone can switch role. Gate pages with `<RoleGate>` and controls with `useRole().can(...)`. Never describe roles as access control.
- Human overrides must go through `useSimulation().override`, `sendRepairCrew` or `commission`, so they are held against the agents (`twin.holdThrottle`) and logged.
- Alert rules live in `src/engine/alerts.ts` as pure functions of the world and forecast. The notification bar only renders them and calls existing simulation actions.
- The scenario desk (`/scenarios`) owns the what-if lab, the scenario impact model, the eight-scenario sweep and team submissions. The Operations page does not run scenarios. `/operator` redirects to `/scenarios`.

## Design system

- The palette and Roboto Mono typography live in `src/styles.css` as semantic tokens. Components use tokens (`bg-primary`, `text-muted-foreground`, `text-critical-text`) and never hard-coded colors.
- There are two token sets: light under `:root`, dark under `.dark`. Dark is the default. A script in the document head applies a saved light choice before first paint. To add a color, define it in both sets and register it in the `@theme inline` block.
- Use reduced-motion-aware Framer Motion for machine state transitions and the shared `.gaia-panel` surface for dashboard panels.
- Text uses plain punctuation: no em dashes and no emojis.

## Quality gates

Before shipping, all of these pass: `npx tsc --noEmit`, `npm test`, `npm run build`, `npx prettier --check .`. The hygiene test (`src/test/hygiene.test.ts`) also guards the repository against removed tooling and banned wording.
